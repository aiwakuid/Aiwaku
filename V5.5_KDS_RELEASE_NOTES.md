# AIWAKU V5.5 — Kitchen Display System

## What changed
- Added a dedicated Kitchen Display screen at `/kds`.
- Added a first-class `orders.fulfillment_status` state separate from payment status.
- Added guarded `kitchen_update_order_status()` RPC with tenant membership checks and audit logging.
- Added realtime refresh for tenant orders in KDS.
- Added kitchen workflow: **new → preparing → ready → served** with cancellation from active stages.
- Added cash-payment lookup/record helpers used by the V5.4 POS.

## Important architecture decision
Financial status (`pending`, `dp`, `lunas`, etc.) must not be reused as kitchen status. A paid order can still be cooking. This separation prevents payment completion from hiding an order from the kitchen.

## Migration
Apply `supabase/migrations/20260820_v55_kds.sql` after the existing production schema migrations. The same SQL is appended to `supabase/schema.production.sql`.
